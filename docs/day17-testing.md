# Day17 隔离测试

在 WSL Ubuntu 的正式项目目录运行：

```bash
cd ~/resq
python3 scripts/day17/run_tests.py
```

不需要正式数据库密码或 JWT。脚本使用已安装的 MySQL、Redis、Java 21、Maven，新建独立实例；MySQL 端口为 13317、Redis 端口为 16317。端口已被占用时立即退出，不停止占用端口的程序。当前业务服务、3306 MySQL、6379 Redis 不参与测试。

脚本在 `/tmp/resq-day17-*` 创建私有目录，用独立 MySQL socket 初始化 `resq_day17`，创建仅能访问该测试库的临时账号。数据库和 Redis 中写入同一个随机标记，集成测试验证端口、库名、账号和标记后才创建夹具。假用户使用 `@example.invalid` 邮箱，假时隙在 2099 年；测试不读取真实用户或时隙。

Maven 使用临时 POM 编译正式源码与测试源码，并将构建产物放入临时目录；不覆盖项目原有、可能被 Git 跟踪的 `target` 文件。原 `pom.xml` 不改动，也无需新增依赖。每次结果保存至 `target/day17-results/<UTC时间>-<随机后缀>/`，包括 `concurrency.json`、JUnit XML/文本、运行日志、最终测试库计数和清理确认。正常完成与异常退出均先停止本次创建的进程，再清理其数据目录。

只运行脚本中的测试白名单，不运行已有的全部 Spring Boot 集成测试。新集成测试默认禁用，必须同时开启 `resq.day17.integration` 并提供脚本的隔离参数才能运行；单独传入开启参数也无法连接默认正式库。所有新增测试均不启动 Spring Boot 上下文，不加载正式应用的数据库/JWT配置。

三组实验均运行 100 和 500 个虚拟线程客户端，统一 JDBC 池上限为 16。每个场景使用独立夹具，并在场景后删除自己的测试记录。

| 组别 | 路径与保护 |
|---|---|
| 无锁模拟 | 仅专用 `day17_unsafe_*` 表；先读、无条件写、独立自动提交；用读取后的屏障强制所有线程读到 AVAILABLE，稳定重现错误 |
| 仅 MySQL | 正式 `ReservationService.create`，正式 MyBatis XML，基于正式 `@Transactional` 的 Spring 事务代理 |
| Redisson + MySQL | 正式 `ReservationLockService` 包裹上述正式事务服务；真实独立 Redis |

报告保存成功/业务冲突/其他错误、锁等待超时子计数、总耗时、吞吐量、P50/P95/P99、最终行内容和有效预约数。安全组通过测试侧计数器测量条件 UPDATE 与 INSERT 调用；禁止改写正式 SQL 来制造对比结果。无锁组的“多条成功”是故意展示的安全失败。模拟组多了一道强制竞态屏障，三组耗时不能据此证明某种生产方案更快。

这是服务层实验，缓存删除后端在比较中统一使用 mock；不包含 HTTP、JWT、网络请求开销、跨 JVM 或跨机器部署。此前用户完成的 100/500 HTTP 结果属于另一组验收。

异常路径分层验证：单元测试检查精确 2 秒参数、禁止未获取锁时调用业务、异常传播、持锁判断和解锁；MockMvc 检查 201/409/503/400 映射；真实数据库/Redis 集成测试检查独立连接可见的提交先于解锁、唯一约束失败后的回滚、业务失败后的重新获锁、2 秒超时、等待中断和缓存失败补偿。Redis 客户端关闭测试使用仅该测试客户端的 2 秒 watchdog，检查提交后清理失败与 TTL 到期释放。完整物理断网、Redis 服务故障及生产 watchdog 时长不由该测试证明。

隔离库初始 DDL 来源是项目中已核查的 Day08 文档和当前 Mapper 的列契约。正式库 `SHOW CREATE TABLE`、索引/约束漂移及测试前后业务数据摘要必须经只读核查另行确认；未获授权读取正式数据库配置时，不能宣称二者完全一致。
