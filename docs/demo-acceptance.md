## 完成交付

- scripts/demo/prepare.py：新 session、镜像构建、默认测试、独立故障 IT、四服务/三卷、空库种子与 50 个并发用户准备。
- scripts/demo/run.py：basic、concurrency、advanced、all、status、cleanup，可显式选择 session。所有写场景有一次性执行保护，失败保留现场并返回非零。
- scripts/demo/common.py：生命周期、精确归属与配置检查、SQL/Redis/HTTP 探针、脱敏报告；复用既有 seed、Compose 启动、模型检查与故障测试，不复制另一套业务实现。
- scripts/http_probe.py：从既有 Compose 验收中提取共享 HTTP 传输；旧验收脚本同步使用并经过完整回归。本机请求显式直连，不使用继承的代理，不自动重放失败写请求。
- scripts/demo/test_demo.py：20 项离线保护测试；docs/demo.md：环境要求、命令、证据范围与主持人提纲。

## 实施中失败记录与修正

本轮总共创建过 5 个 demo session，没有隐藏失败或把它们算为通过：

1. 最早一轮在准备阶段因 Docker 网络短 ID 被过严的完整 ID 检查拒绝，未运行场景。改为核对真实网络名称及归属标签，新增正/反例测试，该 session 已清理。
2. 随后一轮 all 全部通过并清理，作为早期实现验证；不替代上表两轮最终彩排。
3. 一轮分模块中 basic 通过，concurrency 遇到一次 URLError（约 15 秒）后失败；容器健康、未重启、无 OOM。原日志不足以确定其根因，不能直接归咎于代理。没有重试竞争写请求；保留失败记录后清理。随后为回环 HTTP 明确绕过代理，补安全的传输错误类别和子阶段定位，增加回归测试。
4. 上表两轮在上述修正后分别以分模块和 all 完整通过，未放宽业务断言、未关闭限流、未修改正确的业务逻辑。

## 隔离、安全与当前现场

原四容器状态与三个数据卷的前后检查通过。本轮 5 个 demo session 均已清理本次容器/网络/三卷/唯一镜像；各次专用 P0 临时容器和旧部署验收临时资源也已清理。没有启动或重建原 deploy 项目，没有删除原卷。

用户的真实 deploy/.env、真实 JWT 密钥和密码没有读取或展示。合成凭据置于仓库外 0700/0600 的私有目录，运行内存中的 JWT 不输出。两轮公开报告已检查不含合成密码/JWT；清理成功后删除本次 credentials.json、synthetic.env 与 override.json，保留脱敏报告及私有诊断日志。

配置摘要、归属标记、资源 ID、公开断言和耗时可分享；不要把整个私有 session 文件夹或 Maven 日志直接公开。演示配置在 target/ 外，不会因 clean 丢失；公开验收附件另外保存在本任务输出目录。

原业务 Java、测试源码/断言、SQL/schema、Profile、Dockerfile、原 Compose、POM 和种子实现均经哈希确认未改。现有验收脚本仅提取 HTTP 传输，没有弱化原有验收内容。

## 保留的实现边界

- 候补只做入队、去重、排名，没有自动递补；通知只记录日志，没有邮件/短信。
- 延后扫描补偿只作用于演示环境；本次 MQ 归因不等于单独验证扫描调度。advanced 限制 session 不满 1 小时。
- MQ 生产者没有持久化补发/outbox，演示成功不证明任意故障下消息绝不丢失。
- 失败队列引用本次预跑的独立故障 IT（模拟服务异常），与真实数据库消费幂等的实时演示分开标识。
- 不支持对同一场景静默 reset/replay；重复演示必须新建 session。网络传输仍可能受宿主环境影响，失败会明确退出，不掩盖为成功。
- 只验证本机 WSL、已有镜像/依赖缓存，不代替另一台无缓存机器或公开网络部署验收。
